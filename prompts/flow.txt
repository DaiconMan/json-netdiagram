【共通ルール】
- direction は TB（段が上→下に進む）か LR（段が左→右に進む）。layer は段の番号で 0,1,2…（流れの先頭・上流ほど小さい）。col は段と直交する列の番号で 0,1,2…
- 全ノードに layer と col を必ず付ける。同じ layer と col の組み合わせを2つ作らない
- x, y, w, h は使わない（位置とサイズは変換側で計算する）
- type は【種類】の中から選ぶ
- label は1行あたり全角12文字・半角24文字以内。長ければ \n で改行（3行まで）
- edges の from/to は nodes に存在する id だけを使う
- edges の style は solid / dashed / dotted。arrow は向きのある線なら true
- route は straight（直線）/ bus（くし形・カギ形）/ loop（戻り線）
  - 1つのノードから3つ以上へ分かれる線は、すべて "route": "bus" にする
  - bus は to の layer が from より大きい線だけに使う。前の段へ戻る線（差し戻しなど）は "route": "loop"
  - 同じ段の隣の列へつなぐ線（注記など）は "route": "straight"
  - bus を使う親の col は、親と最も先の子の間にある段では空けておく（幹線が親の真下・真横を通るため）
- 線は隣り合う段の間を基本とし、途中のノードの上を通る結び方を避ける（必要なら col をずらす）
- 段を分けて並べる子は、どの段も同じ col の範囲に詰めて揃える。親の col は子の col 範囲の中央付近にする
- group に入れるノードは col が連続する範囲にまとめ、グループ外のノードをその範囲の中に置かない。別グループ同士は col を1つ以上空ける
- 線ラベルの位置は変換側が自動で調整する（label_pos は省略してよい）。ラベルが枠やノードにかかると指摘されたら row_gap（TB）か layer_gap（LR）を増やす
- lanes は使うときだけ書く（使わないなら "lanes": []）。使うときは全ノードをどれか1つのレーンに入れ、レーンごとに col を分ける
- 図全体は幅・高さとも 2400px 程度に収める（1段に並べるのは10個程度まで）
- JSONにコメントや末尾カンマを入れない

【種類（type）】
- ネットワーク: firewall / router / switch / ap / server / vm / cloud / user / storage
- ソフトウェア: client / service / database / queue / external
- 組織: person / dept
- フロー・手順: start / end / process / decision / data / document / subprocess / step
- 資料: box / emphasis / note
【この図のルール（業務フロー）】
- direction は LR。layer は時間の順（左ほど先）
- 担当者・部署ごとに lanes を作り、全ノードをどれかのレーンに入れる。レーンごとに col を分ける（1レーン1列が基本）
- 始まりは start、終わりは end、作業は process、判断は decision（label は「〜？」）、帳票は document、システムへの入出力は data
- 線はすべて arrow: true。前へ進む線は "route": "bus"（カギ形になる）
- decision から出る線には label で「はい」「いいえ」などの条件を書く
- 差し戻しなど前の段へ戻る線は "route": "loop"
- 1つの段に置くのは、レーンごとに1つまで
